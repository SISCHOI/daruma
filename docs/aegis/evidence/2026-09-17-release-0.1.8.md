## 4. npm 阻塞的实测矩阵

| 凭证 | 操作 | 结果 |
|---|---|---|
| GAT（bypass 2FA，用户提供） | `npm stage publish` | ✅ 成功（两个包） |
| GAT | `npm publish`（直接） | ❌ `E_STAGE_REQUIRED`（"该 token 只能发到暂存区"） |
| GAT / session | `npm stage approve`（无 OTP / 假 OTP） | ❌ 404 |
| session（`npm login --auth-type=web` 后） | `npm stage approve`（npm 11.17.0 与 12.0.2） | ❌ 404 |
| session | `npm stage approve --otp=<8 位码>` | ❌ 404（该账号未绑定 2FA，码来源存疑） |
| session | `npm access set mfa=automation <pkg>` | ❌ 403（空 body） |
| 直接调 registry API | `GET /-/stage/<id>` | ✅ 200（stage 存在且可读） |
| 直接调 registry API | `POST /-/stage/<id>/approve` | ❌ 404 `{"error":"staged version \"…\" not found"}` |

【推断】统一解释：npm 对敏感操作要求 proof-of-presence；账号未启用 2FA ⇒ 只有
"推迟 2FA"的 `stage publish` 能通过，approve / access 变更 / 直接 publish 一律被拒
（注册表用 404/403 而非明确的"需要 2FA"错误表达）。

【实测】网络边界：`registry.npmjs.org` 可达（HTTP 200），`www.npmjs.com` 从本机不可达
（超时 / 403）——所以网站侧操作（启用 2FA、UI 批准）必须换设备。
