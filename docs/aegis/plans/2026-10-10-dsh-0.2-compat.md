# DSH 0.2 compatibility adaptation plan

**Status**: Done (headless verified; web panel open) — see `docs/aegis/evidence/2026-10-10-dsh-0.2-compat.md`  
**Branch**: `feat/dsh-0.2-compat`  
**Target hosts**: DSH 0.2.0-rc.2 (latest), 0.2.1-alpha.2 (next), keep 0.1.x hosts working  
**Date**: 2026-10-10

## Confirmed breaks (evidence from e2e run + npm registry)

1. **Peer ranges cap at `<0.1.6`** — host refuses to load dsh-daruma@0.1.8:
   ```
   dsh: skipping profile bundle "dsh-daruma": Error: Plugin dsh-daruma@0.1.8 is 
   incompatible with dsh 0.2.0-rc.2: peerDependencies {"@deepseek-ai/dsh-agent":">=0.1.0-rc.7 <0.1.6",...}
   ```

2. **E2e profile config format changed**:
   - Old: `agent-default-model` as top-level settings key
   - New: `agent-default-model` is a Cordis plugin row in the patch
   - `dsh-settings-file` package gone, replaced by `dsh-settings` + `dsh-config-editor`
   - pi-ai providers now under `llm-pi-ai:` in the profile patch as a plugin config, not standalone `settings.yaml`

3. **Client inject list changed**:
   - daruma declares `@deepseek-ai/dsh-client-runtime` (gone in 0.2.0)
   - available: `dsh-client-connection`, `dsh-client-ui-conversation`, `dsh-client-ui-primitives`

4. **RPC handler signature expanded** (harmless):
   - Old: `handler(endpoint, payload, signal)`
   - New: `handler(endpoint, payload, signal, peer)`
   - daruma passes `{ authority: 'loopback' }` as third arg; 0.2.0's two-arg call ignores it

## APIs daruma uses (checked against 0.2.0-rc.2)

### Host hooks (unchanged)
- `agent/request`, `agent/request-error`, `agent/pre-step`, `agent/turn-stopping`, `agent/disposed` — exact same signatures in 0.2.0-rc.2
- `RequestErrorAction`, `retryPolicy`, `LlmCallConfig`, `ResolvedRetryPolicy` — types intact

### LLM runtime (unchanged)
- `ctx.llm.listModels(provider)` → `Promise<LlmModelInfo[]>` — same
- `ctx.llm.resolveModelInfo(provider, model, signal)` → `Promise<LlmResolvedModelInfo>` — same
- `reasoningEffort` logic in `toFailoverConfig` — advertised efforts still in `info.reasoning?.efforts`

### Settings (structural change, API preserved)
- Old: `ctx.settings.get('llm-pi-ai' as SettingsNamespace)` returned section
- New: `ctx.settings` is `SettingsForms`, `get()` method signature TBD but `describe()` → descriptors
- daruma uses `settings.get('llm-pi-ai')` only in `rpc.ts` → `knownProviders()` / `listCandidates()` fallback

### Session events (unchanged)
- `agent.session.append(type, value)` — same
- `SessionEventMap` module augmentation — same

### Connection RPC (signature expanded, backward-compatible)
- `connection.rpc.handle(channel, handler, options)` — 0.2.0 takes two args, ignores third
- daruma calls `connection.rpc.handle('/dsh-daruma', dispatch, { authority: 'loopback' })` — works as call

## Adaptation steps

### Phase 1: Widen peer ranges (packages/dsh-daruma/package.json)
```json
"peerDependencies": {
  "@deepseek-ai/cordis": "^4.0.1",
  "@deepseek-ai/dsh-agent": ">=0.1.0-rc.7 <0.3.0",
  "@deepseek-ai/dsh-llm": ">=0.1.0-rc.7 <0.3.0",
  "@deepseek-ai/dsh-session": ">=0.1.0-rc.7 <0.3.0",
  "@deepseek-ai/dsh-settings": ">=0.1.0-rc.7 <0.3.0",
  "@deepseek-ai/schemastery": "^3.18.1"
}
```

### Phase 2: Fix client inject (packages/dsh-daruma/package.json dsh.client.inject)
Remove `@deepseek-ai/dsh-client-runtime` (gone in 0.2.0).

### Phase 3: Fix e2e profile (scripts/e2e-failover.mjs)
- Replace standalone `settings.yaml` + `cordis.patch.yml` settings row with inline plugin config
- Move `agent-default-model` from settings section to a Cordis row
- Keep mock provider config under `llm-pi-ai` plugin's `providers` object

### Phase 4: Test & verify
- `pnpm run e2e:failover --dsh .dsh-lab/install-020rc2/.../bin.js` against 0.2.0-rc.2
- `pnpm run e2e:failover --dsh .dsh-lab/install-015rc2/.../bin.js` against 0.1.5-rc.2 (regression)
- Unit tests (99 total)

### Phase 5: Evidence & README
- Land raw e2e output + version-matrix table under `docs/aegis/evidence/2026-10-10-dsh-0.2-compat.md`
- Update README support table: add 0.2.0-rc.2 row
- Commit message: "feat(compat): support DSH 0.2.x (0.2.0-rc.2+) alongside 0.1.x"

## Open questions
- Does 0.2.0 still emit `agent/request-error` with `retryPolicy` populated? (grep says yes, type unchanged)
- Is `ctx.settings.get('llm-pi-ai')` still available, or must daruma switch to `ctx.settings.describe()`? 
  → settings is now `SettingsForms`, `get()` removed; fallback logic must change
- Does the `/dsh-daruma` RPC route still mount on 0.2.0, or is `webServer` inject still required?
  → 0.2.0 `HostConnectionRpc.handle(channel, handler)` no longer takes options, handler gets `peer` arg

## Known risks
- `ctx.settings.get('llm-pi-ai')` may not exist in 0.2.0; daruma's `knownProviders()` / `listCandidates()` fallback could break
- Widening peer to `<0.3.0` means daruma will load on 0.2.1-alpha.x, which may introduce new breaks
